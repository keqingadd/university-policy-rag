# 3 分钟演示脚本（校赛/省赛答辩用）

## 准备
1. 终端执行 `python scripts/build_index.py`（没有索引时跑一次）
2. 另开终端执行 `streamlit run app.py`，浏览器停在首页
3. 再留一个终端，备用跑评测

## 0:00–0:30 开场（讲问题）
"企业知识散落在手册、FAQ、制度文档里，客服和新员工只能全文搜、逐篇翻。通用大模型能答，但会编、而且没有出处。所以我做了一个能溯源的企业知识库问答系统。"

## 0:30–1:00 架构（一句话）
"流程是：文档先做标题感知切片，进 BM25 和向量两路索引，查询时用 RRF 融合排序，取 Top-5 上下文交给大模型生成，答案里带 [1][2] 引用。"

## 1:00–2:00 现场演示（重点）
在输入框依次问（看到答案后指着引用讲解）：
1. "私有化部署需要什么配置？" → 答案 + 引用到「部署与运维手册 · 私有化最低配置」
2. "遇到 429 错误怎么办？" → 引用到 API 指南错误码小节（证明精确关键词命中）
3. "怎么防止内部人员把数据导出去？"（口语化问法）→ 仍命中「安全与合规 · 权限模型」（证明语义兜底）
4. 追问一个知识库没有的问题："你们支持哪些编程语言？" → 展示"无法确定"的拒答（证明不瞎编）

## 2:00–2:40 数据说话
切到终端跑 `python scripts/evaluate.py --mode hybrid`：
"16 道标注题：关键词问法 Hit@1 90%、MRR 0.95；口语化问法混合检索 Hit@5 100%，比单路关键词检索高 16.7 个百分点。检索平均 0.1 毫秒，成本主要在生成。"
（时间够再跑 `--mode bm25` 对比，讲"为什么要混合"。）

## 2:40–3:00 收尾
"后续计划：加 rerank、引用校验、多轮对话和缓存。我想做的是敢让企业用的知识库问答，所以从第一天就把评测和引用做进去。"

## 备用：评委打断时的一句话
- 为什么不用纯向量？→ 专有名词/错误码需要精确命中，纯向量会漏；RRF 融合更稳，评测里有数据。
- 没配大模型怎么演示？→ 系统自动降级为抽取式回答，引用一样在，现场可演示。
