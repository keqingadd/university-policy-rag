# 3 分钟演示脚本（校赛/省赛答辩用）

## 准备
1. 终端执行 `python scripts/build_index.py`（没有索引时跑一次）
2. 另开终端执行 `streamlit run app.py`，浏览器停在首页
3. 再留一个终端，备用跑评测

## 0:00–0:30 开场（讲问题）
"学生问'评贫困生多久一次''勤工助学一个月能打多少小时工'，答案散在教育部规章、省教育厅办法里，全文搜不到，翻文档又慢。通用大模型不知道这些政策，还会编。所以我做了一个能溯源的政策问答助手。"

## 0:30–1:00 架构（一句话）
"流程是：政策原文先做标题感知切片，进 BM25 和向量两路索引；用户提问先做查询改写，把口语映射成政策术语；然后 RRF 融合排序，取 Top-5 交给大模型生成带引用的回答。"

## 1:00–2:00 现场演示（重点）
依次问（看到答案后指着引用讲解）：
1. "家庭经济困难学生认定多久评一次？" → 引用到安徽省认定办法"每学年进行一次"
2. "国家奖学金一年多少钱、多少个名额？" → 引用到资助政策"12 万名、每生每年 1 万元"
3. "勤工助学一个月最多能打多少小时工？"（口语化）→ 引用到勤工助学办法"每月不超过 40 小时"
4. 追问知识库外的问题："我们学校食堂几点开门？" → 展示"无法确定"的拒答

## 2:00–2:40 数据说话
切终端跑 `python scripts/evaluate.py --mode hybrid`：
"16 道标注题：关键词问法 Hit@1 90%、Hit@3 100%；口语化问法 Hit@3/5 100%、MRR 0.92。中间我做了个消融：不加查询改写时口语化 Hit@1 只有 66.7%，加上同义词改写后到 83.3%，这就是我这版最核心的改进。"

## 2:40–3:00 收尾
"后续计划：加 rerank、引用校验、政策版本管理。我想做的是学生真能用、敢用的政策助手，所以从第一天就把引用和评测做进去。"

## 备用
- 没配大模型？→ 系统自动降级为抽取式回答，引用照常，可现场演示。
- 为什么不用纯向量？→ 政策里全是精确字段（10 日、5 个工作日、16000 元），纯向量口语化 Hit@1 只有 50%，有评测数据。
